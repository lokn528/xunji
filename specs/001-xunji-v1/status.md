## 实现过程中发现并修掉的真问题

1. **迁移从未执行** —— `PRAGMA user_version` 默认值是 0 而非 -1，原判断
   `current < 0` 永远为假，建表语句一次都没跑过。17 个测试同时失败暴露了它。
2. **迁移版本号语义错位** —— `user_version` 被写成 `version + 1`，导致升级路径
   判断错误。改为「`user_version = N` 表示前 N 个迁移已应用」。
3. **Tauri 权限缺失** —— `capabilities/default.json` 没声明 `dialog:default`，
   前端的文件选择器会被 Tauri 直接拒绝。`autostart:default` 同样补上。
4. **NSIS 打包跨盘失败** —— tauri-bundler 把 NSIS 解压到项目 `target/release`
   再重命名到 C 盘缓存目录，跨盘 `rename` 报 ERROR_NOT_SAME_DEVICE。解法是把
   `%LOCALAPPDATA%\tauri` 做成指向 E 盘的目录联接，并按 `NSIS_REQUIRED_FILES`
   补齐 13 个必需文件（含单独下载的 `nsis_tauri_utils.dll`）。
5. **右键「发送到 循迹」是空壳** —— `pending_import_paths()` 只在测试里被调用，
   应用完全没处理命令行传来的路径：右键会启动应用但什么都不做。补上
   `AppState.pending_imports` + `take_pending_imports` 命令 + 前端启动时取走
   并导入。已实测：带路径启动 → 自动建卡 → 数据库 `origin = sent_to`。
6. **构建产物双击打开是白屏** —— Vite 默认用绝对路径 `/assets/...`，`file://`
   下解析到磁盘根目录被 CORS 拦掉；即使路径修好，ES module 在 `file://` 下
   仍必被拦。改成相对路径 + 在 `index.html` 里加一段内联兜底脚本，检测到模块
   没跑起来就显示「这是桌面应用，不是网页」的说明页。
7. **无人值守的导入不该报错** —— 右键导入时若没配默认存储位置，交互式导入
   会明确报错让人去设置，但右键导入会直接失败、看起来像坏了。改为右键导入
   退回「仅登记」（文件留在原处，卡片照建），交互式导入保持报错。

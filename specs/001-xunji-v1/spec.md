# Feature Specification: 循迹 v1 —— 本地文件卡片索引

**Feature Branch**: `001-xunji-v1`

**Created**: 2026-10-22

**Status**: Draft

**Input**: 用户描述："循迹"——给你丢过的每个文件发一张"户口卡"（一句话说明 + 截图 + 分类 + 日期），随时能顺着卡片找回它在电脑里的确切位置。本质是"文件和你的记忆之间的连接层"，不是文件管理器。

## 背景

技术型个人用户的桌面积压着大量"过一两周要用"却找不到出处的文献、作业与临时文件。
浏览器收藏夹只存链接且不跨浏览器互通，也记不住"当初为什么收藏"。微信文件传输助手
沦为垃圾场，当天发过的链接第二天就说不清用途。

现有方案各有冲突：批量自动整理类工具（如 ai-file-sorter、Local-File-Organizer）以
自动化搬文件为核心、界面为英文、功能边界过大；paperless-ngx 一类以"接管文件存储"
为核心，与用户"文件留本机、工具只做参谋"的诉求直接冲突。

循迹的定位是给每个文件发一张**户口卡**：一句话说明 + 可选截图 + 分类 + 日期，
点击即定位到磁盘上的确切位置。文件本体始终在本地，循迹只做参谋。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 丢进来的文件自动变成一张卡片 (Priority: P1)

用户把一个 PDF 从桌面拖进循迹（或在资源管理器里右键"发送到 > 循迹"），循迹把它
落到设定好的存储位置，并立刻生成一张卡片：显示名、一句话说明（可先留空标记为
"待写"）、分类、日期、指向磁盘的确切路径。

**Why this priority**: 这是整个产品存在的理由。没有建卡这一步，后面所有能力
（找回、说明、分类）都无从谈起。而且这一条可以独立交付：即便说明永远是空的，
用户已经获得了"路径登记 + 可视化列表"。

**Independent Test**: 拖入一个文件后，检查存储位置出现了该文件、卡片列表出现一张
对应卡片、卡片的路径指向磁盘上真实存在的文件；重启应用后卡片仍在。

**Acceptance Scenarios**:

1. **Given** 设置里已配置默认存储位置，**When** 用户拖入一个文件，**Then** 文件被
   复制到默认位置，卡片以新路径落库，导入页显示成功反馈
2. **Given** 设置里配置了"仅登记不移动"模式，**When** 用户拖入一个文件，**Then**
   原文件留在原地不动，卡片的路径指向原处
3. **Given** 用户在资源管理器中右键选择"发送到 > 循迹"，**When** 循迹启动，**Then**
   选中的文件被同样地导入并建卡
4. **Given** 拖入的是一个文件夹，**When** 导入完成，**Then** 该文件夹整体生成一张
   卡片，且卡片上可展开查看其中的子项
5. **Given** 同一文件已被收录，**When** 再次导入，**Then** 提示"已收录"并定位到
   已有卡片，不产生第二张卡
6. **Given** 目标位置磁盘已满或无写入权限，**When** 导入，**Then** 明确报错并且
   不产生任何半成品卡片

---

### User Story 2 - 给卡片补上"这是干嘛的" (Priority: P1)

用户导入文件后，卡片的说明往往是空的——这正是"用一周后完全不记得"的原因。
用户可以点"让 AI 写说明"，AI 根据文件名与文件类型产出一句话说明和建议分类，
填进输入框；用户确认或改写后才真正保存。也可以自己手写。

**Why this priority**: 补上说明是循迹相对于普通收藏夹的核心差异，也是用户"文件与
记忆之间连接层"这一价值主张的兑现。与 P1 并列：如果只有建卡没有说明，循迹就退化
成了一个花哨的路径管理器。

**Independent Test**: 对一张空说明的卡片点击"让 AI 写说明"，若已配置 API 则输入框
出现 AI 生成的说明与建议分类，用户点保存后卡片显示该说明；若未配置 API，卡片正常
保留且说明仍为空，不报错中断。

**Acceptance Scenarios**:

1. **Given** 卡片说明为空且已配置 AI 供应商，**When** 用户点"让 AI 写说明"，**Then**
   输入框被填入 AI 生成的一句话说明与建议分类，尚未写入卡片
2. **Given** AI 已生成建议，**When** 用户修改文字并点保存，**Then** 卡片显示修改后的
   说明，且标记为非 AI 生成
3. **Given** 卡片已有手写说明，**When** 用户点"让 AI 写说明"，**Then** 原说明不被
   覆盖，AI 结果先进输入框供用户对比
4. **Given** 未配置 API Key，**When** 用户点"让 AI 写说明"，**Then** 提示"AI 不可用，
   可手动填写"，卡片照常存在
5. **Given** AI 请求失败或超时，**When** 用户点"让 AI 写说明"，**Then** 给出明确
   失败提示，卡片与已有数据均不受影响
6. **Given** 用户开启了"仅用文件名分析"，**When** 调用 AI，**Then** 请求中不包含
   文件内容，仅含文件名与文件类型

---

### User Story 3 - 顺着卡片找回文件 (Priority: P1)

桌面上不再堆文件之后，用户需要的是"找回"而不是"存储"。时间线视图按日期分组
倒序展示卡片；分类视图按分类分组。用户点卡片主体直接打开文件，点"位置"按钮
打开文件所在的文件夹并选中该文件。

**Why this priority**: 找回是第二个不可分割的核心价值。与建卡、说明并列构成
"收集 → 理解 → 找回"的完整闭环，缺任何一环产品都不成立。

**Independent Test**: 导入若干文件后，在时间线中按日期找到其中一张卡片，点击
"位置"，系统文件管理器打开并选中该文件；切到分类视图，分类分组与卡片归属正确。

**Acceptance Scenarios**:

1. **Given** 存在多张卡片，**When** 用户打开时间线视图，**Then** 卡片按导入日期
   分组、组内倒序排列
2. **Given** 一张卡片对应的文件仍在磁盘上，**When** 用户点击卡片主体，**Then**
   系统用默认程序打开该文件
3. **Given** 一张卡片对应的文件仍在磁盘上，**When** 用户点击卡片的"位置"按钮，
   **Then** 系统文件管理器打开其所在目录并选中该文件
4. **Given** 某张卡片的源文件已被移动或删除，**When** 用户浏览时间线，**Then**
   该卡片标记为"源文件丢失"，点击"重新定位"可选择新文件并绑定回该卡片
5. **Given** 用户置顶了一张"近期要用"的卡片，**When** 用户打开时间线，**Then**
   该卡片浮在时间线顶部，取消置顶后回到原日期位置

---

### User Story 4 - 管理分类与批量整理 (Priority: P2)

用户按学科或项目给卡片分类（如"数学""毕设""课程作业"）。分类页按分类分组展示
卡片网格，点击某个分类可过滤查看。空分类可一键创建，避免因分类缺失而放弃整理。

**Why this priority**: 分类显著提升"找回"的效率，但没有分类时靠时间线仍能工作。
因此排在三个 P1 之后。

**Independent Test**: 创建两个分类并把卡片分别归入其中，打开分类页可见两个分组
及各自的卡片数量，点击某个分类可过滤。

**Acceptance Scenarios**:

1. **Given** 用户尚未创建任何分类，**When** 打开分类页，**Then** 提供一键创建入口
2. **Given** 存在多个分类，**When** 打开分类页，**Then** 按分类分组展示卡片并显示
   各分类的卡片数量
3. **Given** 用户点击某个分类，**When** 过滤生效，**Then** 只显示该分类的卡片
4. **Given** 用户在卡片上选择新分类，**When** 分类不存在，**Then** 自动创建该分类
   并完成归类

---

### User Story 5 - 配置默认行为与 AI 供应商 (Priority: P2)

用户设置默认存储位置（目录选择器）、落点模式（移动/复制到默认位置，或仅登记不
移动）、AI 供应商与凭据（Base URL、API Key、模型名、温度），并可一键测试连通性。
API Key 存系统凭据库，不以明文写入配置文件。

**Why this priority**: 设置是让上述体验贴合个人习惯的必要条件，但没有设置也能用
默认行为先跑起来，故为 P2。

**Independent Test**: 修改默认存储位置后导入一个文件，检查它落到新位置；填入
API 配置后点"测试连通性"，得到明确的成功或失败反馈。

**Acceptance Scenarios**:

1. **Given** 用户在设置里选择了新的默认存储位置，**When** 导入一个文件，**Then**
   文件落到新位置而非旧位置
2. **Given** 用户在导入前临时指定了落点，**When** 导入完成，**Then** 文件落到临时
   指定的位置，且不影响设置中的默认值
3. **Given** 用户填入了 API 配置，**When** 点击"测试连通性"，**Then** 给出明确的
   成功或失败结果
4. **Given** 用户已配置 AI 供应商，**When** 重新打开应用，**Then** 配置仍然有效
5. **Given** 用户未配置 API Key，**When** 查阅数据文件，**Then** 其中不含明文
   API Key

### Edge Cases

- **源文件被移动/改名/删除**：卡片标记"源文件丢失"并提供「重新定位」，不删除卡片、
  不静默改指到别的文件。
- **源文件无读取权限**：记录失败原因，仍建卡片（无缩略图、无内容分析），不中断导入。
- **目标位置磁盘满 / 无权限**：导入阶段明确报错，不产生半成品卡片。
- **重复导入同一文件**：按 file_path 检出，提示"已收录"而非重复建卡。
- **大文件（>100MB）**：不复制内容，仅登记路径；若为"移动"模式则移动而非复制，
  避免双份占空间。
- **缩略图缓存目录被清**：可重建，不影响卡片数据。
- **AI 返回格式异常 / 内容不合规**：解析失败时提示错误并保留手动填写入口，不得写入
  半截内容。
- **同一文件被拖入多次（并发导入）**：以 file_path 唯一性约束保证最终只留一张卡。
- **分类被删除**：其下卡片不删除，分类置空并可在卡片上重新归类。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持通过拖拽投放导入文件与文件夹。
- **FR-002**: 系统 MUST 提供 Windows 右键"发送到 循迹"入口，接收选中的文件与文件夹。
- **FR-003**: 系统 MUST 提供可配置的默认存储位置，并在导入时允许临时覆盖。
- **FR-004**: 系统 MUST 支持两种落点模式：移动/复制到默认位置、仅登记不移动；默认为
  移动/复制到默认位置。
- **FR-005**: 系统 MUST 为每个导入项生成卡片，字段包含 id、display_name、summary、
  file_path、thumb_path（可空）、category（可空）、origin、ai_generated、created_at、
  updated_at。
- **FR-006**: 系统 MUST 允许说明留空，并将该卡片标记为"待写"，不阻塞导入。
- **FR-007**: 系统 MUST 提供手动触发 AI 分析的入口（卡片上的「让 AI 写说明」），并在
  导入时提供"导入后立即 AI 分析"的勾选项；默认不自动调用。
- **FR-008**: 系统 MUST 将 AI 产出的说明与建议分类填入可编辑输入框，仅在用户确认后
  写入卡片。
- **FR-009**: 系统 MUST 在 AI 不可用（未配置 key）、请求失败、超时或返回异常时降级：
  卡片照常创建，说明留空，提示"AI 不可用，可手动填写"，且不阻塞导入主流程。
- **FR-010**: 系统 MUST 提供"仅用文件名分析（不发送文件内容）"开关，默认开启保守行为。
- **FR-011**: 系统 MUST 仅向 AI 发送生成说明所必需的内容：文件名、文件类型，以及
  开关允许时可提取的文本片段。
- **FR-012**: 系统 MUST 提供时间线视图，按导入日期分组、组内倒序展示卡片。
- **FR-013**: 系统 MUST 提供分类视图，按分类分组展示卡片，并支持点击分类过滤。
- **FR-014**: 系统 MUST 允许创建分类；卡片归类到不存在的分类时自动创建该分类。
- **FR-015**: 系统 MUST 支持卡片置顶与取消置顶；置顶卡片在时间线顶部呈现。
- **FR-016**: 系统 MUST 支持点击卡片打开文件，以及打开文件所在文件夹并选中该文件。
- **FR-017**: 系统 MUST 检测源文件丢失，标记卡片并提供「重新定位」以绑定新文件。
- **FR-018**: 系统 MUST 按 file_path 检测重复导入，提示"已收录"而非重复建卡。
- **FR-019**: 系统 MUST 持久化卡片与设置，使数据在应用重启后仍然可用。
- **FR-020**: 系统 MUST 将 API Key 存入系统凭据库，而非明文配置文件。
- **FR-021**: 系统 MUST 提供 AI 供应商配置（供应商、Base URL、API Key、模型名、温度）
  与连通性测试。
- **FR-022**: 系统 MUST 支持从 OpenAI 兼容的 `/chat/completions` 接口调用 AI，以兼容
  国产供应商与中转站。
- **FR-023**: 系统 MUST 明确报告导入失败原因（磁盘满、无权限等）且不产生半成品卡片。
- **FR-024**: 系统 MUST 支持卡片缩略图；v1 采用图片类文件自动生成缩略图，其余类型
  允许用户手动粘贴截图。
- **FR-025**: 系统 MUST 支持文件夹导入：整体生成一张卡片，并可展开查看子项。
- **FR-026**: 系统 MUST 支持对 >100MB 的大文件仅登记路径、不复制内容。
- **FR-027**: 系统 MUST 不把文件本体上传到任何服务器；数据库只存路径与元数据。
- **FR-028**: 系统 MUST 保持文件本体在本地，AI 调用只发送 FR-011 列举的最小内容。

### Key Entities

- **Card（卡片）**：一件被收录事物的身份记录。核心是 file_path——指向磁盘上实体的
  绝对路径。summary 是必填语义字段（可暂空并标记待写）。thumb_path 可空。
  origin 记录导入方式（imported_moved / imported_kept / sent_to）。
  ai_generated 标记该说明是否由 AI 生成。
- **Category（分类）**：单选分类（如"数学""毕设"）。v1 单选，二期可扩展多标签。
- **Settings（设置）**：默认存储位置、落点模式、AI 供应商配置、缩略图缓存目录等。
  API Key 单独存于系统凭据库。
- **Thumbnail（缩略图）**：卡片的可视预览，存于缓存目录，可重建，不影响卡片数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从拖入一个文件到看到对应卡片，全程无需离开导入页，且不出现
  "半成品"卡片。
- **SC-002**: 用户在任意时刻能通过时间线或分类找到一件东西并双击打开它，
  定位过程不超过 3 次交互。
- **SC-003**: 导入 100 个文件的场景下，时间线首屏渲染在 1 秒内完成，滚动保持流畅。
- **SC-004**: 桌面在完成一次批量导入后不再新增堆积文件——所有被导入文件均落在
  设定位置或明确登记为"仅登记"。
- **SC-005**: AI 不可用时，导入成功率与 AI 可用时完全一致（100%），不出现因 AI
  失败导致的导入失败。
- **SC-006**: 100% 的卡片在应用重启后仍可访问，卡片数据零丢失。
- **SC-007**: 数据文件与配置文件中不含明文 API Key。
- **SC-008**: 源文件丢失时，100% 被正确标记并可重新定位，卡片不被删除。

## Assumptions

- 首个版本面向 Windows 11，依赖系统 WebView2（已确认本机具备 v155）。
- 文件夹导入 v1 取「整体建卡 + 可展开子项」，不递归展开为多张独立卡片。
- 截图来源 v1 取「图片类自动生成 + 其余类型手动粘贴」；PDF 首页缩略图列入后续版本。
- 网页链接收集尚未实现；循迹 v1 只聚焦本地文件，后续版本再单独设计链接收集。
- AI 供应商通过 OpenAI 兼容接口接入，具体供应商由用户在设置页选择，默认以
  OpenAI 兼容配置为基线。
- 单用户单机型使用，不引入账号体系与云同步。
- 本期为 v1 首个可交付切片；全文检索、PDF 工具、云同步均为后续候选，不在本期范围。

## Out of Scope

- 文件内容编辑与 PDF 工具（另立项）。
- 云同步、多端账号体系。
- 全文检索（PDF/Word 正文索引）——二期候选。
- AI 自动归档决策（AI 只建议，不自动搬文件）。
- 浏览器插件与网页链接收集（后续版本实现）。

## Dependencies

- Tauri 2 桌面壳（需要 Rust 工具链与 MSVC 构建工具）。
- 本地 SQLite（单文件，随应用数据目录存放，备份即复制文件）。
- OpenAI 兼容的 AI 接口（可由用户自配供应商；未配置时功能降级而非报错）。
